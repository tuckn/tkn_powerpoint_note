# AI によるスライドの説明と資料の要約

`--context` で生成する説明のしくみ、再利用の条件、上限、失敗したときの対処、独自の文章 profile の作り方をまとめます。
基本の使い方は [README](../../README.md#32-ai-による説明を付ける) を参照してください。

## 処理の流れ

`export --context` と `pull --context` は、1つの PowerPoint を次の順に処理します。

1. PowerPoint のファイルを直接読み取り、スライドごとの文字と構造を抽出します。PowerPoint は起動しません。
2. 対象のスライド（`--slides`・`--section` の指定がなければ、ノートに含めるすべてのスライド）ごとに、保存済みの AI の結果を探します。
3. 結果のないスライドだけを、デスクトップ版 PowerPoint で画像にします。
4. 画像と根拠データを AI に送り、スライドごとに1回ずつ説明を生成します。1枚終わるたびに、結果を保存します。
5. 説明のあるスライドの組み合わせが前回と違えば、説明をまとめて AI に送り、資料の要約を1回生成します（条件は「[資料の要約を作り直す条件](#資料の要約を作り直す条件)」）。
6. ノートを書き、ノートが参照しなくなった結果を削除します。

`--dry-run` は 2 までを行い、AI の呼び出し回数（`plannedAiCalls`）を表示します。
接続先の設定と実行ファイルの有無も確かめますが、認証・通信・PowerPoint の起動・ファイルの保存は行いません。

## AI に送るもの

スライドごとに、次の2つを送ります。

- PowerPoint が描いたスライドの画像（幅は `generation.limits.image_width`）。
- 抽出した根拠データ（JSON）。タイトル、セクション、図形ごとの種類・文字・位置・色・コネクタの接続、表、グラフの値、SmartArt の文字、発表者ノート、コメントを含みます。

根拠データは、空白のない JSON にし、空の項目を省きます。
図形の位置（`box`）は、`[左, 上, 右, 下]` をスライドの幅と高さに対する千分率で表します。
色は、図形ごとに重複を除いた一覧です。
スライドの番号と、資料内の位置は送りません。
完全にスライドの外にある要素は、`extraction.off_slide: append` のときだけ、別の項目（`off_slide`）として送ります。画像には写りません。

資料の要約には、スライドの画像を送らず、各スライドの番号・タイトル・生成済みの説明だけを送ります。
`--slides`・`--section` で選ばなかったスライドは、画像・根拠データ・生成済みの説明のどれも送りません。
PowerPoint のファイルそのものと、設定ファイルも送りません。

## 説明の再利用

説明は、スライド単位で保存し、次の内容がすべて同じなら再利用します。

| 判定に含めるもの | 変えると |
| --- | --- |
| スライドと、そのスライドが使うレイアウト・マスター・テーマ・画像・グラフ・発表者ノート・コメントの内容 | そのスライドだけ生成し直します。 |
| AI に送る根拠データ（抽出の設定を含む） | 根拠データが変わったスライドを生成し直します。 |
| 画像の幅（`image_width`）と、資料のスライドの大きさ（縦横の寸法） | すべてのスライドを生成し直します。 |
| 文章の profile の名前・言語・プロンプト・出力スキーマ | すべてのスライドを生成し直します。 |
| 接続先の種類（provider）、モデル、推論の強さ | すべてのスライドを生成し直します。 |

次のものは判定に含めません。

- スライドの位置（番号）と、PowerPoint のファイル名・保存場所。スライドを挿入・並べ替え・削除しても、ほかのスライドの説明は再利用します。
- PowerPoint がスライド番号のプレースホルダーに書き込む番号。
- 文書プロパティ、ファイルの更新日時、ZIP の格納方法。内容を変えずに保存し直しただけでは、生成し直しません。
- Markdown のテンプレートと表示文言、このツールの版、タイムアウト、上限の設定。テンプレートを変えた場合は、保存済みの出力から、AI を呼ばずにノートを作り直します。

マスターやテーマを変えると、それを使うすべてのスライドの見た目が変わるため、該当するスライドを生成し直します。
ほかのツール（Web 版、変換ツール、スライドを生成するプログラムなど）が書き出したファイルを、初めてデスクトップ版 PowerPoint で保存した場合は、PowerPoint がファイルの中身を書き直すため、内容を変えていなくても一度すべてのスライドを生成し直します。
その後の保存し直しでは、生成し直しません。
1つの資料の中に、内容がまったく同じスライドが複数ある場合は、1回の呼び出しの結果をそれぞれに使います。

再利用は、同じノートの `img/<PowerPointのファイル名>/` の中だけで行います。
出力先の違うノートの間では、結果を共有しません。
同じ出力先に別の PowerPoint を書き出した場合は、前の PowerPoint の結果を引き継ぎません。

### 資料の要約を作り直す条件

資料の要約は、内容が今の PowerPoint と対応している説明をすべて使って作ります。
説明のあるスライドの組み合わせ（番号と、それぞれの説明）が前回と変わったときに、1回生成し直します。

`--slides`・`--section` で対象を絞った実行では、要約に使う説明が、すべて今回の対象に入っている場合だけ生成します。
対象外のスライドの説明を使うことになる場合は、その説明を AI に送らないために、要約を作り直しません。
以前の要約はノートに残し、古いことを示す注意書きを付けて、結果の `warnings` で知らせます。
`--slides`・`--section` を付けずに `--context` を実行すると、要約を作り直します。

たとえば、30枚の資料を `--slides "1-10"`、`"11-20"`、`"21-30"` の3回に分けて実行すると、1回目に1～10枚目の要約を作り、2回目と3回目は要約を作り直しません。
最後に `--slides` なしで実行すると、スライドの説明はすべて再利用し、30枚分の要約を1回だけ生成します。

## 説明の状態

ノートの Frontmatter の `contextStatus` は、ノートにある説明全体の状態を表します。

| `contextStatus` | 意味 |
| --- | --- |
| `not-generated` | 説明をまだ生成していません。 |
| `current` | ノートにあるすべてのスライドの説明が、保存済みの PowerPoint と対応しています。 |
| `partial` | 説明を生成していないスライドがあります（`contextOmittedSlides`）。 |
| `stale` | 説明の生成後に内容が変わったスライドがあります（`contextStaleSlides`）。資料の要約だけが古い場合（スライドの挿入・並べ替え・削除の後や、対象を絞った実行の後）も含みます。 |

`--context` を付けない `pull` は、説明を消さずに残し、内容が変わったスライドを `stale` にします。
`--context` を付けて実行すると、変わったスライドと資料の要約だけを生成し直します。
`--slides` や `--section` で一部だけを対象にした場合も、対象外のスライドの説明は残ります。

## 上限と、超えたときの動き

| 状況 | 動き |
| --- | --- |
| AI に送るスライドが `max_slides` を超える | その資料は、AI を呼ぶ前にエラーにします。`--slides` で範囲を分けるか、`--max-slides` で上限を上げます。済んだスライドは数えないため、範囲を分けて繰り返すと、全体を処理できます。 |
| 1枚の根拠データが `max_input_chars` を超える | そのスライドだけを飛ばし（結果の `skippedSlides`）、残りを続けます。ノートのそのスライドには、理由を示します。 |
| 資料の要約に渡す説明の合計が `max_input_chars` を超える | 要約だけを作らず、結果の `warnings` に示します。スライドの説明は保存します。以前の要約があれば、古いことを示してノートに残します。 |
| 画像化が `max_render_seconds` を超える | その資料の処理を止めます。PowerPoint が一時コピー（`source.pptx`）を開いたままなら、閉じてから再実行します。 |

上限の設定を変えても、生成済みの説明は再利用します。

## 画像化

- 画像化は Windows とデスクトップ版 PowerPoint で行います。別のプロセスから PowerPoint を操作し、時間の上限を設けます。
- 元のファイルではなく、一時フォルダへ写したコピーを、読み取り専用・ウィンドウなし・マクロ無効で開きます。
- PowerPoint は、利用者が使っているプロセスを共有することがあるため、このツールは PowerPoint を終了しません。開いたコピーだけを閉じます。
- マクロ（`vbaProject`）や ActiveX を含むファイルと、ハイパーリンク以外の外部参照を含むファイルは、開く前に拒否します。リンクの更新を尋ねるダイアログで処理が止まることと、外部の資源を読みに行くことを避けるためです。対象外のスライドにある場合も拒否します。
- 失敗した場合は、PowerPoint 側のエラーの最後の行をメッセージに出します。全文は `--verbose` で確認できます。

## 失敗したときの対処

- 一部の PowerPoint で失敗しても、ほかの PowerPoint のノートは作成・更新します。失敗した対象は、結果の `results` に `error` と理由を出力します。
- AI の呼び出しが失敗した場合、その資料のノートは更新しません。済んだスライドの結果は保存されているため、同じコマンドを再実行すると、残りから続けます。自動の再試行はしません。
- AI の出力がスキーマに合わない場合や、管理マーカーを含む場合は、その出力を採用しません。返された内容は `rejected.json`、理由は `usage.json` に残ります。
- 処理中は、ノートの隣にロックファイル `.<ノート名>.lock` を置きます。強制終了で残った場合は、ほかに実行中のコマンドがないことを確かめてから、手で削除します。
- 中断（Ctrl+C）しても、完了したノートと、保存済みの AI の結果は残ります。

## 独自の文章 profile を作る

文章の profile は、次の8ファイルの組です。
同梱の [`default-ja`](../../src/powerpoint_note/context_profiles/default-ja/) を写して、書き換えるのが簡単です。

| ファイル | 役割 |
| --- | --- |
| `prompt.md` | スライドの説明のプロンプト。`{{language}}` を1か所に書きます。 |
| `output.schema.json` | スライドの説明の出力スキーマ |
| `template.md` | スライドの説明の Markdown テンプレート。先頭の YAML に、版（`version: 2.0.x`）、言語（`language`）、表示文言（`labels`）を書きます。 |
| `deck-prompt.md` / `deck-output.schema.json` / `deck-template.md` | 資料の要約のプロンプト・出力スキーマ・テンプレート |
| `note-template.md` | ノート全体のテンプレート（Presentation Map、要約、スライドの並び） |
| `source-template.md` | スライド1枚分のテンプレート（説明、Extracted Text、発表者ノート、コメント） |

置き場所は、`generation.prompt_profile_dirs` に書いた親フォルダの下の、profile 名のフォルダです。
設定の `prompt_profile`、または `--profile` で名前を指定します。

守る決まりは次のとおりです。処理の前に検証し、合わない場合はエラーにします。

- テンプレートの項目は `{{name}}` で書き、決められた項目を1回ずつ使います。空のときに省く部分は `{{#name}}` と `{{/name}}` で囲みます。入れ子にはできません。
- 出力スキーマの項目は変えられません。スライドは `summary`・`sections`（`heading`・`body`）・`uncertainties`、要約は `summary`・`key_points`（`text`・`slides`）・`uncertainties` です。説明文（`description`）や文字数の制約は追加できます。スキーマの参照（`$ref`）は使えません。
- `labels` には、同梱の profile と同じ名前の文言をすべて書きます。
- 管理マーカーの文字列 `powerpoint-note:` は、どのファイルにも書けません。

プロンプトと出力スキーマを変えると、説明を生成し直します。
テンプレートと表示文言だけを変えた場合は、AI を呼ばずにノートを作り直します。
