# export --context を実務で使った結果と改善の候補

2026-11-27 に、利用側のプロジェクト（非公開）で `export --context` を使った結果から、改善の候補をまとめた引き継ぎ。
顧客の資料のため、資料名・パス・内容は書かない。
同じプロジェクトで使った tkn-excel-note の引き継ぎ（`tkn_excel_note/docs/handoffs/export-context-feedback.md`）と、内容が重なる項目がある。

## 使い方

業務システムの運用の全体図（PowerPoint、3枚）を、AI に読ませて設計書のレビューに使うため、Markdown にした。
図が中心の資料で、四角の中の文字、矢印、札（番号の付いた小さな図形）、範囲の枠で意味を表している。
顧客がコメントで修正を依頼し、作成者が取り消し線・赤字で直して、コメントに返信している。

- 版：`tkn-powerpoint-note 0.7.0`（Windows、PowerPoint デスクトップ版）
- コマンド：

  ```shell
  tkn-powerpoint-note export <copy.pptx> --output <note.md> --context --generator copilot-high --force
  ```

  元の資料は SharePoint の同期フォルダにあり、メンバーが編集中なので、作業用のフォルダにコピーしてから入力にした。
- 先に `--dry-run` で AI の呼び出し回数（4回）を確かめた。

## 規模と時間

| 項目 | 値 |
| --- | --- |
| スライド | 3枚（文字のある図形 64・102・87、画像 4・7・0、コメントと返信 8・4・1） |
| AI の呼び出し | 4回（スライドごとに1回と、資料の要約）。約165秒 |
| ノート | 約 39 KB |
| 失敗 | なし |

## 効果

文字の抽出だけのノート（`--context` なし）と、説明付きのノートで、資料の理解を比べた。
先に20問を決め、文字の抽出だけのノートで答えられるかを採点してから、説明付きのノートで採点し直した。

| ノート | 答えられた | 一部だけ | 答えられない |
| --- | ---: | ---: | ---: |
| 文字の抽出だけ | 2 | 10 | 8 |
| 説明付き | 19 | 1 | 0 |

- 文字の抽出だけでは、矢印の向き、範囲の枠の内と外、札の番号がどの四角に付いているか、業務の分類（2段の枠）が分からなかった。
- 説明は、スライドの画像と1つずつ照合した。37業務の番号・名前・担当・分類、札の位置、矢印、範囲の枠は、すべて正しかった。
- 説明の「不確かな点」が、図とコメントの食い違い（コメントで頼まれた語が図にない、など）を挙げており、レビューの指摘の候補になった。
- 「一部だけ」で残った1問は「コメントがどの図形に付いているか」で、下の 2 のとおり、ノートに情報がないためである。

## 改善の候補

優先度は、今回の作業で困った度合いで付けた。
「現状」は確かめた事実、「案」は提案で、まだ設計していない。

### 1. 修正の痕跡（取り消し線・文字の色）を Extracted Text に出す（高）

- 現状
  - Extracted Text は文字だけで、書式は出さない（`docs/reference/note-format.md`「Extracted Text」）。
  - 今回の資料には、取り消し線の付いた文字の範囲（`strike="sngStrike"`）が4か所、赤（`FF0000`）の文字の範囲が57か所あった。
  - 取り消した語と、その代わりに赤字で書いた語が、Extracted Text では続けて出る。例：「（取り消し線の語）（赤字の語）」が1つの文として読める。
  - AI の説明は、画像から取り消し線に気づき、「不確かな点」に書いていた。ただし、赤字が修正した箇所であることには触れていなかった。また、文字の抽出だけを読む使い方では、取り消し済みの語を正として読むおそれがある。実際に、こちらのレビューで、取り消し線の前後の関係を一度読み違えた。
- 影響
  - コメントで修正を頼まれて直した資料では、取り消し線と赤字が「何を直したか」の根拠になる。
- 案
  - Extracted Text に、書式の印を付けて出す選択肢（例：`~~取り消し~~`、`{color:FF0000}…{/color}`）。文字の範囲（run）の単位で付ける。
  - 色は、テーマの色と明るさの調整も RGB に直して判定する（tkn-excel-note の引き継ぎの 1 と同じ）。
  - AI への根拠データにも印を入れ、「取り消し線の語は削除済みとして読む。赤字は修正した箇所として扱う」と指示する。

### 2. コメントが付いている図形と文字を出す（高）

- 現状
  - 「コメント」の節は、スライドごとに、作成者・日時・本文・返信を並べる。どの図形に付いたかは出さない。
  - pptx の新しい形式のコメント（`ppt/comments/modernComment_*.xml`）には、付いた先が入っている。今回の7件のスレッドは、どれも図形の ID（`ac:spMk id`）を持ち、うち2件は、図形の中の文字の範囲（`ac:txMk cp len`）と位置（`p188:pos`）も持っていた。
  - 「当該フォルダは〜ですので、修正下さい」のように、付いた先が分からないと意味が決まらないコメントがあった。説明の AI は画像とコメント本文から推測していた。
- 案
  - コメントの行に、付いた先を添える。例：`- 作成者 (日時) [対象：<図形の文字の冒頭> / 文字「<txMk の範囲の文字>」]: 本文`。
  - 図形に文字がないとき（画像・グループなど）は、図形の名前と種類を出す。スライドに付いたコメントは「スライド全体」とする。
  - AI への根拠データにも付いた先を入れる。

### 3. 図形のまとまりを Extracted Text に残す（中）

- 現状
  - Extracted Text は、要素を上から下、左から右の順に、平らに並べる（`note-format.md`「Extracted Text」）。
  - 今回の資料には、グループが31個あった。四角とその中の札、枠とその中の四角の関係は、並びからは分からない。
  - 「答えられない」の8問は、取り消し線の1問（1 を参照）を除くと、どれも、札がどの四角に付くか、四角がどの枠に入るか、四角がどの凡例の色か、番号と業務名のどれが組か、が分からないことによる。
- 案
  - グループを、字下げした入れ子の項目で出す選択肢。グループに名前があれば、見出しの代わりにする。
  - 凡例の色で意味を表す資料のため、図形の塗りの色を添える選択肢（例：`[塗り:#DDEBF7]`）。凡例の図形の色と同じかどうかを、読み手が突き合わせられる。
  - 範囲の枠（大きな四角で、ほかの図形を囲むもの）の内側にある図形を、枠の下にまとめるかは、誤判定のおそれがあるので慎重に決める。少なくともグループは、ファイルの構造どおりなので確かである。

### 4. 矢印のつながりを出す（中）

- 現状
  - コネクタは出さない（`note-format.md`「Extracted Text」）。
  - 今回の資料のコネクタは39本で、始点が図形につながっているもの（`a:stCxn`）は1本だけだった。ほとんどの矢印は、図形に接続されていない線である。そのため、ファイルの構造だけでは、どこからどこへの矢印かが分からない。今回は、説明の AI が画像から読み取った。
- 案
  - 両端が図形につながっているコネクタは、`- 矢印: <始点の図形の文字> → <終点の図形の文字>` の形で出す。ファイルの構造どおりなので確かである。
  - つながっていない線は、端の座標に最も近い図形を推定して出す選択肢。出すときは「推定」と明記する。効果が小さければ、画像からの説明に任せる。

### 5. タイトルのないスライドの見出し（低）

- 現状：3枚ともタイトルのプレースホルダーがなく、見出しが「スライド 1: —」になった。どれが何のスライドかが、見出しと Presentation Map から分からない。
- 案：タイトルがないときは、一番上の大きな文字の図形を、見出しに添える（例：「スライド 1: —（<文字>）」）。または、AI の説明があるときは、説明から短い題を作り、AI が作ったことを示す。

### 6. コメントの日時のタイムゾーン（低）

- 現状：コメントの日時が `2026-11-11T01:17:48.620` のように、タイムゾーンなしで出る。ファイルの値は UTC と思われる（日本の勤務時間に合わせると9時間ずれる）。
- 案：`Z` を付けるか、ローカルの時刻に直してオフセットを付ける。

### 7. コピーから作ったときの、元の場所（低）

- 現状：コピーを入力にしたため、Frontmatter の `sourceFullPath` がコピーの場所になった。元の資料（SharePoint の同期フォルダ）の場所はノートに残らない。
- 案：元の場所を記録する選択肢（例：`--source-origin <path or URL>`）。または、`pull` の source 同期のように、元の場所から読み、ファイルはコピーに逃がしてから開く。

## 確かめていないこと

- 1 の赤（57か所）が、すべて修正の印か。凡例などで、もともと赤を使っている文字も含むかもしれない。
- 2 の `txMk` の `cp`・`len` が、段落をまたぐときに、どう数えるか。
- 6 のコメントの日時が UTC か。PowerPoint の画面の表示と比べていない。
- `copilot-high` のときに、トークン数が記録されるか（tkn-excel-note では `unknown` だった）。
